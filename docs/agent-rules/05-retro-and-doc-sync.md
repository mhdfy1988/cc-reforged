# 05 复盘与文档同步

## 1. 每轮总结要求

1. 修复线程每轮结束后必须给出：核心问题、处理方法、为何这样做、剩余问题。
2. 审查结束后必须补充：是否真正解决目标、是否引入新风险、下一轮应收哪条链。
3. 用户明确点名的协作问题，应沉淀到规则或文档，不只口头说明。

## 2. 审查后的文档同步

1. 每轮审查有结论后，先更新文档再进入下一轮。
2. 默认同步：
   - [current-repair-backlog.md](../stages/current-repair-backlog.md)
   - 阶段边界变化时再同步 [recovery-repair-plan.md](../recovery/recovery-repair-plan.md)
3. 每轮至少写清：
   - 该轮是否通过
   - 新增完成文件或切片
   - 当前主线与精确停点
   - 全仓余额或热点变化
4. 如果本轮是类型修复闭环，`PASS` 后必须重新刷新任务状态：
   - 先生成一份 fresh 全仓 `typecheck` 输出文件，不要复用旧 `.codex-typecheck*.txt`
   - 基于这份 fresh 快照统计剩余错误数、涉及文件数
   - 更新第一梯队热点文件列表
   - 把本轮完成文件加入最近闭环
   - 基于最新热点重新刷新任务队列
   - 把新的当前主线和下一批候选写入看板
5. 当前轮未独立审查 `PASS` 前，不得提前刷新到下一轮任务；只能把当前状态标记为待审查、待返工或待刷新。
6. 未完成上述刷新前，不得对外说“已经切到下一轮”；最多只能说“代码修复通过，正在刷新任务状态”。

## 3. 回写精简规则

当某条经验已被反复验证且跨轮复用时，应评估是否回写到
[AGENTS.md](D:/agent_project/claude-code-reforged/AGENTS.md) 的精简规则中。
