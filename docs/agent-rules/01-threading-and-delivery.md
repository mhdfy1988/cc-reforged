# 01 子线程协作与交付

## 1. 主线程与子线程分工

1. 默认采用双线程协作：主线程负责文档、方案收束、代码评审；子线程负责实现与修复。
2. 用户明确要求主线程只做文档和评审时，主线程不直接修改业务实现文件。

## 2. 子线程交付规则

1. “完成”必须以真实文件改动为准，不能只返回状态说明。
2. 子线程交付结果必须包含：修改文件清单、关键改动点、验证命令与结果、阻塞点。
3. 缺上述信息时按未完成处理。
4. 修复线程不得在未被明确授权时主动更新 `stages/current-repair-backlog.md` 等看板文档；看板由主线程在独立审查结论落地后统一刷新。

## 3. 子线程失效处理

1. 第一次仅状态回复：中断并重派更窄任务。
2. 连续两次仅状态回复：关闭并重建线程，任务收窄到更小单元。
3. 无实际改动前，不得对外宣称“已完成/已进入评审”。

## 4. 任务切分规则

1. 任务优先按文件级或模块级边界拆分，避免一次下发过大范围。
2. 大任务优先拆为：工程配置、构建适配、依赖补全、主链运行、权限与状态收口。
3. 每个子线程默认只负责一个清晰阶段或清晰文件集。
4. 每轮开始或从中断恢复后，主线程必须先刷新计划任务，明确“派发 / 等待 / 主线程复核 / 独立审查 / 文档更新”的当前阶段，再派发或等待子线程。
5. 如果旧子线程句柄失效，先更新计划中的线程状态，再重建线程；不得在没有计划任务的情况下临时扩展分析或跳过派发。

## 5. 中断与网络异常规则

1. 网络中断、线程断开或用户打断后，不能默认子线程状态可信。
2. 恢复后必须重验：线程是否存活、是否有真实改动、是否有验证结果。
3. 只有状态消息且无代码结果时，统一按未完成处理。

## 6. 本地检索 fallback 规则

1. 当前 Windows 环境如果 `rg.exe` 返回 `Access is denied`，不要反复尝试同一路径。
2. 直接改用 `Get-ChildItem -Recurse | Select-String` 做本地源码检索。

## 7. 长任务等待规则

1. 子线程进入真实长任务后，主线程应持续等待，不提前收工。
2. 长任务包括：`npm/pnpm install`、`typecheck`、构建、大规模扫描、大量测试。
3. 短等待只用于识别无效线程；确认其真实执行后切换长等待。
4. `wait_agent` 超时不等于线程失败。
5. 用户明确“可持续等待”时，优先更长等待窗口。
6. 只要全仓 `typecheck` 还没清零，主线程就不能把项目口径说成“已完成/已收口”；每次只能结束“当前文件/当前切片”这一轮，然后继续下一主线，除非用户明确要求暂停、改方向或接受阶段性停点。
7. 只要下一动作明确、且没有外部硬阻塞，主线程就不能停在“抓完报错 / 读完现场 / 做完分析”这类中间态；必须继续推进到“已派单并等待”或“已派审查并等待”。
8. “当前热点已锁定但还没派修复线程”不是合法停点；若发生在回合末，按流程错误处理。
9. 如果当前回合被平台、网络、额度、机器重启或用户打断强行中止，下一回合恢复时必须先执行恢复清单，而不是直接继续新分析。

## 8. 防停恢复清单

1. 先确认当前主线文件和当前阶段：派发 / 等待 / 主线程复核 / 独立审查 / 文档更新。
2. 读取最新 `docs/stages/current-repair-backlog.md` 当前主线与最近闭环。
3. 读取最新 `.codex-typecheck.txt` 或重新生成 live `typecheck` 过滤，确认目标文件当前错误是否仍存在。
4. 如果上一轮已有修复线程或审查线程，先核验其是否有效、是否已有真实代码结果，再决定复用、等待或重建。
5. 只有完成以上 4 步后，才能重新派单或继续等待；不得从“印象中的上一步”直接跳转。

## 9. 线程复用与轮换规则

1. 默认策略是“复用优先 + 定期轮换”，不是“永远复用”或“每次新建”。
2. 满足以下条件时优先复用旧线程：
   - 任务域未切换（同一文件链或同一故障域）
   - 旧线程最近一轮有真实代码产出
   - 响应速度和执行质量未明显下降
3. 满足以下任一条件时立即重建线程：
   - 连续空回包或仅状态回复
   - 连续偏航（偏离指定文件或目标）
   - 响应显著变慢或上下文噪声明显增大
   - 额度异常、网络异常、线程断连
   - 任务域发生切换（例如从 Logo 链切到 MCP 服务链）
4. 周期性轮换建议：
   - 修复线程：每完成一个阶段或连续 `3-5` 轮后重建
   - 审查线程：更短生命周期，建议每 `1-2` 轮重建
5. 轮换前必须先把状态沉淀到文档（至少 `stages/current-repair-backlog.md`），确保“记忆在文档里，不在线程里”。
