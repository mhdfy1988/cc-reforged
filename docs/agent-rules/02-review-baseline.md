# 02 评审基线与高风险检查

## 1. 评审前提

1. 评审前必须确认子线程已产出真实文件修改。
2. 评审结论必须基于：实际文件变更、实际验证输出、当前仓库状态。
3. 无 diff 或无改动时，不给“通过”口径。

## 2. 完整审查基线

1. 默认执行“完整审查本轮所有改动文件”，不做抽查。
2. 审查至少核对：
   - 目标报错/问题是否收敛
   - 是否引入静默空实现、假成功、过宽类型桥接、边界放宽
3. 仅在用户明确接受时，才可临时降级为抽查。
4. 非 git 仓库也不得跳过审查，应按子线程修改清单逐文件核对。

## 3. 高风险入口额外检查

适用范围：运行时入口、服务入口、daemon 入口、命令入口、权限入口。

1. 检查是否把未恢复功能伪装为成功。
2. 检查是否把异常路径静默吞掉。
3. 检查是否把内部类型错误桥接成外部“假稳定接口”。
