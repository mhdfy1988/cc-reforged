# CCR Desktop 体验增强路线

## 1. 文档目标

本文档记录 FE13 的长期体验方向。它不是马上开做的实现清单，而是防止后续 UI 增强偏离主线。

当前原则：

```text
Desktop 是 CCR Core 的客户端壳。
App Server 是稳定协议层。
体验增强只能复用这条链路，不能另写一套业务运行时。
```

## 2. 第一优先级：不打断聊天主流程

主聊天页继续保持三段式：

```text
顶部状态栏
-> 中间任务现场
-> 底部输入栏
```

后续增强要围绕这个布局展开：

- 侧栏可以折叠，但不能影响主聊天宽度自适应。
- 顶部状态可以点开详情，但默认只保留工作区、模型、上下文、登录状态。
- TodoWrite 继续用角落浮层，不占主聊天区。
- 权限请求和工具结果保留在时间线内，详情默认折叠。

## 3. 候选体验能力

| 能力 | 用户价值 | 第一版边界 |
| --- | --- | --- |
| 侧栏折叠和宽度持久化 | 给聊天区更多空间 | 只保存 UI 偏好，不改变路由 |
| 状态详情弹层 | 查看 provider、model、context、auth、App Server 状态 | 只读展示，不直接改配置 |
| 默认全屏 / 窗口状态恢复 | 打开 CCR 后优先获得足够工作区空间 | 第一版默认最大化启动；如果已有用户窗口偏好，优先尊重用户偏好 |
| 会话下拉 | 快速切换当前 thread | 只用 App Server `thread/list` 和 `thread/start` |
| 历史会话 | 恢复之前的任务现场 | 等 Core 持久化更稳定后再做 |
| 文件区 | 展示工作区文件、引用、产物 | 只读浏览优先，不直接绕过权限写文件 |
| diff 预览 | 展示工具造成的文件变化 | 等 P21 文件事件字段补齐后做 |
| 上下文文件管理 | 选择要给模型参考的文件 | 走 App Server 协议，不让 renderer 读任意文件 |
| 设置页模型配置 | 切换 provider / model / context 上限 | 走 Core 配置服务，不直接写 token |
| 日志页增强 | 排查 App Server / provider / tool 错误 | 继续使用脱敏日志 |

## 4. 推荐推进顺序

第一轮先做低风险 UI 壳能力：

1. 侧栏折叠和宽度持久化。
2. 默认全屏 / 窗口状态恢复。
3. 顶部状态详情弹层。
4. 会话下拉和新建会话整合。

第二轮等事件字段补齐后再做任务增强：

1. 文件事件卡和 diff 预览。
2. 工具结果详情面板。
3. 上下文文件管理。

第三轮再做长期能力：

1. 历史会话恢复。
2. 多工作区切换。
3. 插件、MCP、Skill 的统一管理入口。

## 5. 明确不做的事

短期不做：

- 不在 renderer 里重写 Core 会话逻辑。
- 不在 Desktop 里直接实现 LLM provider。
- 不绕过 App Server 读写 OAuth token。
- 不让每个页面各自调用一套业务接口。
- 不为了 UI 效果硬解析 stdout、stderr 或模型自然语言。

如果某个 UI 需要新字段，先补 App Server event contract，再补前端展示。
